Conditions in plain words

These concepts extend the existing guided sentence editor. They let a mission author say that something must be false, that any one choice is enough, that a rule covers every matching thing, or that two names must be different. The screen never asks the author to type PDDL.

The proposed interaction.

A condition is a sentence or a labelled group of sentences. The author chooses the group meaning first, then fills only legal fact and name choices. The generated PDDL remains visible in its existing preview, but it is not an input field.

Concept 1 · One fact must be false

Use the same sentence, with a visible “not” choice

The sentence reads naturally and does not introduce a second editing mode.

For this review

Questions the implementation decision depends on

  1. Does “must not be true” read clearly?

    Alternatives are “must be false” and “is not the case.” The first matches the existing “is true” choice most directly.

  2. Is “Any one of these is enough” unambiguous?

    The key question is whether a reviewer understands that two displayed lines are alternatives rather than two requirements.

  3. Do “for every” and “for at least one” need examples beside them?

    The proposed editor previews a concrete sentence when the type has known objects, such as “every sector: sector-a, sector-b.”

  4. Should equality be phrased only as “same” and “different”?

    Those words avoid mathematical notation and say exactly why the comparison affects which action combinations exist.

  5. Should nested groups be limited on screen?

    The core accepts nesting. The proposal allows it but collapses completed inner groups to a one-line summary so the action remains readable.
